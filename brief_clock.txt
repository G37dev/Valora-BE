1. Core Concept
VIVALORA membutuhkan satu sumber waktu resmi yang dibaca oleh financial engine. Di Production sumber waktunya adalah real server/system time. Di Development/Staging sumber waktunya dapat diganti menjadi waktu simulasi yang bisa di-set exact oleh developer.

2. Step 1 - Create BusinessClock Service
Ini adalah pekerjaan pertama. Semua logic time-based Gold Installment harus mengambil 'current time' dari BusinessClock, bukan langsung dari server clock di banyak tempat.

Staging / REAL
Return real current time.
Staging / SIMULATED
Return simulated_now dari config/table.

Return simulated_now dari config/table.
Target tahap ini sederhana: Installment Service cukup bisa meminta satu nilai current business time dari satu sumber.

4. Step 3 - Generate Standard next_due_at Deterministically
Saat Standard Installment aktif, backend membuat dan menyimpan due date. Untuk rule yang sedang dipakai: monthly due mengikuti tanggal anniversary pada 00:00 WIB.
activated_at09 Oct 2026 23:00 WIB        |        vderive monthly calendar anniversary        |        vnext_due_at09 Nov 2026 00:00 WIB
Setelah tersimpan, due date itu tidak perlu dihitung ulang dari nol setiap kali user membuka halaman.

5. Step 4 - Create Installment Due Checker
Checker adalah business logic yang membandingkan financial deadline dengan BusinessClock. Jangan taruh semua logic langsung di cron/scheduler.
business_now = BusinessClock.current()        |        vfind Standard positions:next_due_at &lt;= business_nowAND scheduled amount still unpaid        |        vmark/evaluate OVERDUE        |        vcalculate applicable Late Penalty
Important
Scheduler hanya trigger. Financial rule harus tetap berada di Due Checker supaya function yang sama bisa dipakai Production scheduler dan manual Development testing.
6. Step 5 - Add Manual Staging Controls
Sebelum bikin UI yang rapi, developer cukup menyediakan internal endpoint / admin action untuk dua hal:
Set Business Time.
Run Installment Due Checker.
Dengan dua action ini, lifecycle satu bulan bisa dites dalam beberapa detik.

8. Step 6 - Production Scheduler
Setelah manual checker terbukti benar, baru scheduler production dibuat. Scheduler tidak menghitung rule sendiri; scheduler hanya menjalankan Due Checker secara periodik.
Production Scheduler        |        vInstallment Due Checker        |        vBusinessClock.current() = REAL TIME        |        vevaluate due / overdue positions
Contoh scheduler dapat berjalan setiap 1 menit. Keterlambatan scheduler tidak boleh mengubah financial effective timestamp.

10. Definition of Done - Phase 1
Standard position can be created normally with real contract timestamps.
next_due_at is stored correctly using Asia/Jakarta calendar semantics.
Staging Business Clock can jump to any exact date/time.
Changing simulated_now does not mutate created_at, activated_at, next_due_at, or maturity_at.
Manual checker can move an unpaid position from RUNNING to OVERDUE at the exact due boundary.
Checker can be run repeatedly without creating duplicate overdue/penalty events.
Production is hard-blocked from SIMULATED clock mode.
Phase 1 Target
Position: next_due_at = 09 Nov 2026 00:00. Simulated time 08 Nov 23:59:59 -&gt; RUNNING. Simulated time 09 Nov 00:00:00 + Run Checker -&gt; OVERDUE. Jika scenario ini reliable dan repeatable, fondasi time simulation dianggap valid.
